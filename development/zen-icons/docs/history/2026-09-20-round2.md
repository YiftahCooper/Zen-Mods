# Round 2 repairs — Zen Icons 0.2.0

## Scope and acceptance boundary

Implement the user's Round 2 feedback in Zen Icons; Better Zen Folders owns its
separate repairs and the shared colour/menu contracts. The user confirmed that
unsaved-tab behaviour works normally and chose separate visibility defaults for
tabs, folders and spaces. Preserve already accepted restore, empty-folder and
child-colour behaviour. Do not launch Zen or operate the user's desktop.

## Repairs

- Tab Default clears the static override through Zen's existing callback, then
  restores a remembered native favicon or a local Places favicon. Blank is a
  separate persistent square selection. No page reload or guessed network URL.
- Delayed favicon lookup cannot replace a newer selection, navigation or native
  favicon, nor write after tab closure/browser replacement/mod disposal.
- Space Default previews the native 8px grey circle and opts out of Zen's global
  squircle rule. Default folder SVG sizing fits and centres within its button.
- Sine preferences expose independent tab/folder/space provider defaults and
  hidden-category lists. All initially enabled; filter changes are temporary
  unless explicitly saved. Category navigation still reveals and jumps to its
  destination. Unavailable custom-provider preferences are preserved.
- Preference serialization supports punctuation/JSON-looking custom category
  names. Image-only caller restrictions are not saved as user preferences.

## Evidence

Inspected installed Zen 1.22.2b / Gecko 156 code in the local omni.ja archives:
ZenPinnedTabManager's reset callback, tabbrowser setIcon, TabStateCache, Places
favicon dataURI contract, native space-dot styling and global squircle styling.
Inspected installed Sine settings support before adding preferences.json.

Regression tests were observed failing before repairs, including cached favicon
restoration, context defaults, actual runtime Default/Blank selection, category
serialization and asynchronous races. Two isolated Chromium CSS tests fail
against the previous installed stylesheet and pass against this candidate.

Final `npm run check:sine`, with `ZEN_ICONS_PLAYWRIGHT_MODULE` enabled:
**124 passed, zero failed, zero skipped**. This includes packaging and a Windows
deployment/rollback fixture. `git diff --check` passed. Headless layout fixtures
block network and do not use Zen or any user browser profile.

Independent read-only review found no remaining Critical/Important issues after
repairs. Its final Minor JSON-looking category case was corrected and covered
before the 124-test final run.

## Limits

Offline tests do not establish actual Gecko chrome rendering, live Sine settings
appearance, restart persistence or user acceptance. A previously customized tab
with neither a remembered favicon nor a local Places entry (notably private
tabs) retains the native no-icon fallback until the page supplies its icon.

No commit or publication performed. Existing unrelated working-tree changes are
preserved.
